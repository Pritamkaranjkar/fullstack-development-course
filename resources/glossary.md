# Glossary

| Term | Meaning |
|------|---------|
| Client | The program, usually a browser, that sends requests |
| Server | The program that receives requests and sends responses |
| HTTP | The protocol used for clients and servers to communicate |
| HTTPS | HTTP with encryption so the content is harder to read or change during transit |
| API | A defined way for programs to talk to each other |
| DNS | A system that maps domain names like `example.com` to IP addresses |
| IP address | A unique number used to identify a machine on a network |
| Port | A numbered door on a computer that a service uses to listen for traffic |
| URL | A full web address that includes protocol, host, path, and optionally query data |
| Status code | A number returned by a server to explain the result of a request |
| localhost | A special hostname that points to your own computer |
| CORS | A browser rule that blocks cross-origin requests unless the server allows them |
| package.json | The main metadata file for a Node.js project, including scripts and dependencies |
| dependency | A library or package the app needs to run |
| devDependency | A library used only during development, such as a watcher or linter |
| npm | Node Package Manager, used to install and manage JavaScript packages |
| Repository | A project folder tracked by Git |
| Commit | A saved snapshot of your project in Git |
| .gitignore | A file that tells Git which files or folders to ignore |
| Node.js | A JavaScript runtime that can run outside the browser |
| Request | A message sent from the client to the server |
| Response | A message sent from the server back to the client |
| Full stack | The combination of frontend, backend, database, and deployment concerns |

_Add new terms as each module is taught._
